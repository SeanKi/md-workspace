# Tiptap 시험판 — MDXEditor 기능을 얼마나 덮는가

기준: 2026-10-03 · 시험판 `apps/md-tiptap` 0.1.0 · 계획서 [Mobile_Editor_And_Block_Sync_Plan.md](Mobile_Editor_And_Block_Sync_Plan.md) Phase 0

## 만든 것

```
packages/md-bridge/       마크다운 ⇄ ProseMirror. 원본 보존 직렬화 (React·Tiptap 없음)
packages/editor-tiptap/   Tiptap 편집기 · 툴바 · 코드블록/Mermaid · 이미지 · 표 키
apps/md-tiptap/           Tauri 시험판 (Windows 앱 + 브라우저)
```

기존 두 앱(MD Notepad · MDSyncNote)은 건드리지 않았다. `editor-core` 에는 하위 경로
내보내기(`"./src/*"`) 한 줄만 더했다 — 새 편집기가 이미지·링크·진단 모듈을 MDXEditor 없이 가져다 쓰려고.

```bat
npm run tiptap                 :: 시험판 실행 (tauri dev)
npm run tiptap:web             :: 브라우저로 (http://localhost:1430)
npm run test:roundtrip -- <폴더>   :: 왕복 시험 (파일을 쓰지 않는다)
```

## 왕복 시험 — 실제 노트 760개 (4.1MB)

사용자의 노트 폴더 두 곳 + 이 저장소 `docs/`. 읽기만 했다.

| 항목 | 결과 |
|---|---|
| 열리지 않은 문서 | **0** (MDXEditor 는 `<` 가 든 문서를 정규화해야 열렸다) |
| 열고 손대지 않고 저장 → 바이트 동일 | **760/760 (100%)** |
| 원문과 묶인 블록 | 15,567/15,567 (100%) |
| 모든 블록을 고쳤다고 치고 새로 써도 같은 뜻 | **740/760 (97.4%)** |
| 가장 느린 문서 (읽기+스키마+직렬화, Node) | 547ms / 91KB |

**"고친 블록만 새로 쓴다"** 가 핵심이다. 문단 하나를 고치면 파일에서 그 문단만 바뀐다
(브라우저에서 확인 — 색 span 이 든 문단 끝에 글을 덧붙이면 diff 는 그 한 줄).

### 새로 써도 뜻이 달라지는 20개

| 원인 | 수 | 판단 |
|---|---|---|
| 표 뒤에 `|` 없는 줄이 이어진 것 — GFM 은 그 줄을 표의 행으로 읽는다. 다시 쓰면 빈 칸을 채워 넣는다 | 10 | 화면은 같다. 비교가 빈 칸까지 세서 다르다고 나온다 |
| `<B></B><b>…</B> </B>` 같은 짝이 엉킨 태그, `` `\\|` `` 를 담은 표 | 소수 | 원래 문서가 모호하다. 고치지 않으면 원문 그대로 나간다 |
| 줄 첫머리 들여쓰기가 섞인 목록·인용 | 소수 | 다시 쓰면 들여쓰기를 표준으로 맞춘다 |

### MDXEditor 때 문제가 해결된 것

| 문제 (README "아직 안 되는 것") | 지금 |
|---|---|
| 저장하면 `p.62~65` → `p.62\~65`, `A_B` → `A\_B` | 손대지 않은 블록은 원문 그대로. 고친 블록도 **다시 읽어 뜻이 같다는 것이 증명되는 만큼** 이스케이프를 걷어낸다 (`norm.js unescapeMinimal`) — `[[위키링크]]`, `snake_case`, `drag&drop` 그대로 |
| `<br>` · `A <- B` · XML 로그가 든 파일을 못 연다 → 정규화 300줄 | MDX 가 아니라 GFM 으로 읽으므로 그냥 열린다. 모르는 태그는 **원문 조각**으로 보이고 그대로 저장된다 |
| 표를 여러 칸에 걸쳐 선택 못 함 → `tableSelect.js` | ProseMirror 표라 원래 된다 |
| 글자마다 문서 전체 직렬화 (268KB 한 글자 0.59초) | 글자마다 직렬화 없음. 저장할 때 고친 블록만 (견본 문서 9ms) |

## 알아 둘 것

- **`.image/` 는 점으로 시작하는 숨김 폴더라 Obsidian 이 파일 목록과 그림 표시에서 무시한다.**
  Obsidian 에서도 같은 노트의 그림을 봐야 한다면 이름을 바꾸는 편이 낫다 (`images.js` 의 `IMAGE_DIR` 한 곳)
- **큰 그림은 넣을 때 줄인다** — 1MB 넘거나 긴 변이 2560px 넘으면 긴 변 2560px · WebP 85% (`images.js shrinkImage`). 기본은 **원격이 붙은 저장소의 문서만** (설정: 원격 저장소만 · 항상 · 안 함).
  폰 사진을 붙이면 클립보드가 PNG 로 바꿔 22MB 가 되어 동기화가 시간 초과로 밀렸다. 설정에서 끄거나 크기를 바꾼다.
  이미 넣은 그림은 건드리지 않는다
- **문서에서 지운 그림은 저장할 때 `.image/.mdtrash/` 로** — 다른 문서가 쓰고 있으면 남긴다. 되돌리기로 돌아오면 다음 저장 때 꺼낸다
- **동기화 단추** — 원격이 붙은 저장소가 있을 때만 켜진다. 누르면(그리고 앱이 뜰 때) 전체 점검: 바뀌지 않았다고 적힌 문서도 내용으로 견주고, 그림이 원격에 정말 있는지 본다
- 할 일 항목과 일반 항목이 한 목록에 섞이면 목록 전체를 할 일 목록으로 열고, 상자가 없던 항목은 글머리표로 보인다
- 시험판은 탭이 없다. 한 번에 문서 하나

## 링크 — 시행착오 기록 (MDX v0.13.0 에 이어서)

MDX 때의 교훈은 "**화면의 href 를 믿지 말고 노드에게 물어라**" 였다(lexical 이 `https://` 를 붙였다).
Tiptap 은 링크 표시(mark)가 마크다운에 적힌 주소를 그대로 들고 있어 그 문제는 없다.
대신 아래 다섯 가지를 겪었다. 브라우저 시험으로는 **하나도 드러나지 않았고**, 실제 WebView2 를
원격 디버그 포트로 붙잡고 진짜 마우스 입력(Ctrl 포함)을 넣어서야 보였다.

| 증상 | 원인 | 지금 |
|---|---|---|
| Ctrl+클릭하면 팝업 창이 따로 뜬다 | Tiptap Link 가 `target="_blank"` 를 붙이고, WebView2 는 새 창 요청을 처리하는 쪽이 없으면 **팝업 창을 연다** | `HTMLAttributes: { target: null, rel: null }` + DOM `click`·`auxclick` 을 **캡처 단계**에서 먼저 막는다 (`links.js`) |
| 링크 넣기 창이 안 뜬다 | `window.prompt` — Tauri 창에서 믿을 수 없다 | 링크 풍선(`LinkBubble.jsx`), Ctrl+K |
| 다른 문서는 열리는데 `#제목` 자리로 안 간다 | `linkNav.followHref` 가 다른 문서를 열 때 `openFile(경로)` 만 넘겨 **`#제목` 을 버린다**. 게다가 옛 `revealText.js` 는 DOM 을 뒤져서 ① 탭 전환 직후엔 **이전 문서 화면**을 뒤지고 ② DOM 선택은 ProseMirror 가 다음 그리기에서 **덮는다** | `follow()` 가 `openFile(경로, { heading })` 로 넘기고, 편집기가 **문서 모델**에서 제목을 찾아 선택·스크롤한다 (`reveal.js`). 새 탭이면 그 탭의 편집기가 만들어진 뒤에 한다 (`SplitEditor` 의 `reveal`) |
| Ctrl+클릭이 아무 일도 안 한다 (조용히) | 클릭 처리 안의 지역 변수 `follow`(Ctrl 을 눌렀나) 가 **같은 이름의 함수 `follow` 를 가렸다** — `TypeError` 가 콘솔에만 남았다 | 이름을 `go` 로. 실제 앱의 예외는 CDP 로 받아 봐야 보인다 |
| 저장소 밖에서 연 문서의 `[[노트#제목]]` 이 안 넘어간다 | 이름 찾기가 "이 문서의 폴더 **한 층** → 등록된 저장소" 만 봤다. Ctrl+O 로 연 `link-vault/index.md` 에서 `deep/깊은 폴더/노트B.md` 는 어느 쪽에도 없다. 시험 때는 link-vault 를 저장소로 등록해 둬서 드러나지 않았다 — **사용자의 설정 파일 그대로** 다시 띄워서야 보였다 | 찾는 차례를 Obsidian 처럼: 이 문서가 든 저장소(볼트) → **이 문서의 폴더와 그 아래 전부** → 나머지 저장소 |
| `[[노트]]` 가 그냥 글자다 | GFM 에 없는 문법 | 꾸밈(decoration)으로만 링크처럼 — 파일은 그대로. 이름으로 찾는다: 지금 폴더 → 저장소 전체, 점 폴더 제외 (`lib.rs find_note`) |

### 시험 — 실제 앱에서 11가지 (모두 통과)

`[글](sub/다른글.md)` · `%20` 든 주소 · `<꺾쇠 주소>` · 확장자 없는 주소 · `[[노트]]` ·
`[[노트#제목]]` · `[[노트|별칭]]` · `[[#제목]]` · `[글](#제목)` · `[글](다른.md#제목)` · 웹 주소.
Ctrl+클릭과 "풍선 → 주소 누르기" 두 길 모두. 도착한 뒤 **커서가 그 제목에 있는지**까지 본다.

```bash
# 실제 앱을 디버그 포트로 띄우기 (사용 중인 창과 겹치지 않게 identifier 를 바꾼다)
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333 \
  npx tauri dev --config '{"identifier":"com.smallproject.mdtiptap.linktest"}'
# 그 뒤 ws://127.0.0.1:9333 로 Runtime.evaluate · Input.dispatchMouseEvent(modifiers: 2 = Ctrl)
```

내 노트에서 찾은 것: Notion 에서 내보낸 링크(`%E1%84%86…` — 한글이 **자모로 쪼개진(NFD)** 채
퍼센트 인코딩)는 가리키는 폴더 자체가 저장소에 없어 어느 편집기로도 열리지 않는다.
